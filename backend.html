🧪 แล็บคณิตศาสตร์ Color Dodge Blending (สูตรสร้างภาพร่างดินสอ)

ทดลองปรับค่า Gaussian Blur Kernel และความสว่างภาพต้นฉบับ เพื่อสังเกตผลลัพธ์ Color Dodge

ค่าความสว่างพิกเซลภาพ Grayscale (I): 180
ค่าความสว่างภาพ Inverted Blur (B): 120
สูตรคำนวณ Color Dodge: min(255, (I * 256) / (255 - B + 1))
ตัวเศษ (I * 256): 46,080
ตัวส่วน (255 - B + 1): 136
ผลลัพธ์พิกเซล Dodge: 255 (กระดาษขาว)
ทำไมสูตรนี้ถึงสร้างลายเส้นดินสอได้? เมื่อภาพ Invert ถูกเบลอด้วย Gaussian Filter บริเวณที่เป็น "ขอบของวัตถุ" (High-frequency edge) จะมีค่าตัวส่วนต่ำมาก ทำให้การหารผลักค่าพิกเซลบริเวณนั้นลงมาเป็นสีเข้ม (เกิดเส้นดินสอ) ส่วนบริเวณที่เป็นพื้นผิวเรียบจะถูกเร่งค่าเข้าใกล้ 255 (กลายเป็นกระดาษขาว)

🎨 ทฤษฎี Color Splash (ดูดสีเด่นผ่านระบบสี HSV)

ทำไมต้องแปลง BGR ➔ HSV? เพราะระบบสี HSV แยก Hue (เนื้อสี 0-179) ออกจากความสว่าง ทำให้สร้าง Mask คัดกรองสีได้แม่นยำแม้ในจุดที่มีเงาตกกระทบ

hsv = cv2.cvtColor(bgr, cv2.COLOR_BGR2HSV)
mask = cv2.inRange(hsv, lower_bound, upper_bound)
color_part = cv2.bitwise_and(bgr, bgr, mask=mask)
gray_part = cv2.bitwise_and(gray_bgr, gray_bgr, mask=~mask)
result = cv2.add(color_part, gray_part)

🛡️ Concurrency Guard: SQLite WAL Mode

ในการทำงานแบบมัลติโหนด Webhook จะทำการ Write ผลลัพธ์กลับลง DB ขณะที่ Frontend Polling กำลัง Read อย่างต่อเนื่อง หากใช้โหมดปกติ SQLite จะเกิดปัญหา database is locked

PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA busy_timeout = 5000;
💡 WAL (Write-Ahead Logging) ยอมให้คำสั่ง Read ทำงานพร้อมกับคำสั่ง Write ได้ โดยผู้อ่านจะอ่านจากสแนปช็อตเดิมและผู้เขียนจะเขียนลง Log ไฟล์แยก

🧠 คลังจุดตายที่อาจารย์มักจะเจาะถามฝ่าย Backend (Defense Cheat Sheet)

ท่องจำ 6 ประเด็นนี้ไว้ให้ขึ้นใจ รับรองตอบได้อย่างมั่นใจและได้คะแนนเต็ม

1. ทำไมถึงเลือกใช้ Webhook แทนที่จะให้ Backend ทำ Polling วนลูปถาม AI Server?

ตอบ: เพราะการสร้างภาพใช้เวลาหลายวินาที การให้ Backend Polling ตลอดเวลาจะกิน CPU, Bandwidth และเพิ่ม Connection Overhead มหาศาล การใช้สถาปัตยกรรมแบบ Event-Driven Webhook ช่วยให้ทั้งสองระบบเป็นอิสระต่อกัน (Decoupled) และส่งผลลัพธ์กลับมาทันทีที่ GPU ทำงานเสร็จในระดับมิลลิวินาที

2. ในการทำ Color Dodge ใน OpenCV ทำไมถึงต้องใช้ cv2.divide แทนการเขียนสูตรคณิตศาสตร์ใน Python ตรงๆ?

ตอบ: เพราะฟังก์ชัน cv2.divide() ถูกคอมไพล์ในระดับ C++ ด้วยคำสั่ง SIMD/AVX ทำให้ประมวลผลเมทริกซ์พิกเซลระดับล้านพิกเซลได้เร็วกว่าลูป Python กว่า 100 เท่า และมีกลไกป้องกันการหารด้วยศูนย์ (Zero-division saturation) ในระดับฮาร์ดแวร์โดยอัตโนมัติ

3. ทำไมถึงเก็บไฟล์ภาพผลลัพธ์ลงบน Disk แทนที่จะเก็บเป็น Binary BLOB ใน Database?

ตอบ: เพื่อป้องกันปัญหา Database Bloat และลด Memory Pressure บนฐานข้อมูล การเก็บไฟล์ลง Disk ทำให้สามารถส่งไฟล์ผ่าน Static File Streaming ได้รวดเร็ว และง่ายต่อการย้ายไปเชื่อมต่อกับ Object Storage อย่าง AWS S3 หรือ MinIO ในอนาคต

4. ทำไมถึงใช้ secrets.compare_digest() ในการตรวจสอบ Secret Key แทนการใช้ == ปกติ?

ตอบ: เพื่อป้องกันช่องโหว่ด้าน Timing Attack ครับ ตัวดำเนินการ == จะหยุดทำงานทันทีที่พบตัวอักษรแรกที่ไม่ตรง ทำให้ผู้โจมตีสามารถจับเวลาความเร็วของการตอบสนองเพื่อเดารหัสผ่านได้ แต่ compare_digest จะใช้เวลาเท่ากันเสมอทุกครั้งไม่ว่าจะตรงหรือไม่ตรง

5. หาก AI Server เกิดดับหรือแฮงก์ไประหว่างประมวลผล Backend มีกลไกรับมืออย่างไร?

ตอบ: เรามีระบบ Stalled Watchdog และ Timeout Guard ในฟังก์ชัน _check_and_apply_timeout() หากงานใดค้างอยู่ในสถานะ 'processing' เกินกว่าเวลาที่กำหนด (เช่น 120 วินาที) ระบบจะอัปเดตสถานะเป็น 'failed' พร้อมระบุข้อผิดพลาด Timeout อัตโนมัติ ป้องกันไม่ให้ออเดอร์ค้างในระบบตลอดกาล

6. ทำไมถึงรันงาน Image Tools ผ่าน ThreadPoolExecutor แทนการรันบน Async Loop ปกติ?

ตอบ: เพราะการประมวลผลภาพใน OpenCV เป็นงานแบบ CPU-bound Synchronous Computation หากรันบน Async Event Loop หลักของ FastAPI จะเกิดการบล็อกเธรด ทำให้ไม่สามารถรับคำขอ HTTP ของผู้ใช้คนอื่นได้ การส่งไปรันใน ThreadPool ผ่าน _run_in_pool() จึงเป็นไปตามข้อปฏิบัติ Non-blocking I/O ที่ถูกต้อง

7. ทำไม Backend (Node 2) ถึงต้องสื่อสารกับ AI Node ผ่าน Nginx พอร์ต 80 และแนบ Header X-LUMA-INTERNAL-SECRET?

ตอบ: เป็นเรื่องของการแบ่งแยกโครงสร้างเครือข่ายและความปลอดภัยแบบ Inter-Service Security ครับ: 1) การใช้ Nginx เป็น Ingress Reverse Proxy บนพอร์ต 80 ช่วยปิดกั้นพอร์ต 7860 ภายในของ AI Server ไม่ให้เปิดเผยโดยตรง และรองรับการทำ Timeout 300s กับ Payload ขนาดใหญ่ 50MB ได้อย่างเป็นระบบ และ 2) Header X-LUMA-INTERNAL-SECRET ทำหน้าที่เป็น Shared Token ยืนยันว่าคำขอที่เข้ามายังคิว AI มาจาก Backend ที่ได้รับอนุญาตเท่านั้น ป้องกันการถูกยิงคำขอก่อกวนโดยตรงจาก Client ครับ

"ทำไมถึงต้องตอบกลับด้วย HTTP 202 Accepted แทนที่จะเป็น HTTP 200 OK ที่มีรูปภาพกลับมาเลย?"

📐 1. VAE Spatial Downsampling & Divisible by 8 Explorer

คำนวณมิติ Latent Tensor จากขนาดภาพจริงตามฟังก์ชัน enforce_max_resolution

f = 8x factor
Original Input: 500 x 700 px (Invalid: 500%8 = 4)
Integer Division Math: new_w = (500 // 8) * 8 = 496
Adjusted Safe Pixel Resolution: 496 x 704 px (Divisible by 8)
VAE Latent Space Tensor Shape: [1, 4, 62, 88] (Batch, Channel, H/8, W/8)
ทฤษฎีในข้อสอบ: ใน Latent Diffusion Model (LDM) ตัว VAE Encoder จะบีบอัดภาพด้วยอัตราส่วน 8 เท่า (f = 8) เพื่อลดมิติในการคำนวณจาก 512×512×3 (786,432 ค่าใน Pixel Space) เหลือเพียง 64×64×4 (16,384 ค่าใน Latent Space) ทำให้ประหยัดการคำนวณถึง 48 เท่า! หากขนาดภาพไม่หาร 8 ลงตัว ตัวเลขมิติ Latent จะเกิดเศษทศนิยม ทำให้ Tensor Shape เกิด Dimension Mismatch ทันที

                    ⚠️ Q1: "ถ้ามีคนกดยิงพร้อมกัน 10 คน ทำไม VRAM ของเธอไม่เต็ม (OOM)?"
                

                

                    คำตอบสั้นและเด็ดขาด: "เพราะเราออกแบบ FIFO Task Queue บน queue_manager.py ครับ เมื่อ Request เข้ามาพร้อมกัน ระบบจะตอบรับเข้าคิวด้วย HTTP 202 Accepted ทันที แต่ Background Worker จะดึงงานไปรันบน GPU ทีละ 1 งานเท่านั้น (Concurrency = 1) ทำให้ VRAM ของ RTX 3070 ใช้งานเสถียรที่งานเดียวเสมอ ไม่มีการแย่งทรัพยากรกันครับ"
                

            


            
            

                

                    ⚠️ Q2: "ทำไมขนาดภาพต้องหารด้วย 8 ลงตัวเสมอใน Image Processing?"
                

                

                    คำตอบสั้นและเด็ดขาด: "เพราะตัวเข้ารหัส VAE (Variational Autoencoder) ของ Stable Diffusion มีอัตราส่วนการย่อ (Downsampling Factor) เท่ากับ 8 เท่า (f = 8) เพื่อบีบอัดภาพลงสู่ Latent Space เช่น ภาพขนาด 512×512 พิกเซล จะถูกย่อลงเหลือ Latent Tensor ขนาด 64×64 หากมิติภาพหารด้วย 8 ไม่ลงตัว จะทำให้ขนาดของ Latent Tensor เกิดเศษทศนิยม และเกิดข้อผิดพลาด Dimension Mismatch ใน Layer ของ UNet ทันทีครับ"
                

            


            
            

                

                    ⚠️ Q3: "ทำไมถึงเลือกส่งภาพกลับเป็น WebP แทนที่จะเป็น PNG หรือ JPEG?"
                

                

                    คำตอบสั้นและเด็ดขาด: "เป็นการประยุกต์ใช้ความรู้เรื่อง Image Compression ครับ ไฟล์ PNG ดั้งเดิมที่ออกจากโมเดลมีขนาด 2-4 MB ต่อภาพ เมื่อต้องส่งผ่านเครือข่าย LAN แบบ Distributed จะสร้าง Network Bottleneck สูง การบีบอัดเป็น WebP (Quality 92, Method 6) ช่วยลดขนาดไฟล์ลงถึง ~80% เหลือเพียง 200-400 KB โดยที่สายตามนุษย์แยกไม่ออก ช่วยลด Latency บนเครือข่ายลงได้มากกว่า 6 เท่าครับ"
                

            


            
            

                

                    ⚠️ Q4: "ถ้าเน็ตเวิร์ก LAN สะดุดหรือ Backend ดับไป ภาพที่เจนเสร็จจะหายไหม?"

                    ⚠️ Q5: "ทำไมต้องมีฟังก์ชัน clear_vram_cache() ทั้ง ๆ ที่ PyTorch มี Garbage Collector อยู่แล้ว?"
                

                

                    คำตอบสั้นและเด็ดขาด: "เพราะ PyTorch ใช้ Caching Allocator ครับ เมื่อ Tensor ถูกลบ PyTorch จะยังคง 'จองพื้นที่ VRAM ก้อนนั้นไว้' (Reserved Memory) เพื่อไม่ให้เสียเวลาขอ Allocation ใหม่จากไดรเวอร์ หากรันต่อเนื่องหลายสิบงาน Reserved Memory จะสะสมจนเต็ม 8GB การสั่ง torch.cuda.empty_cache() ร่วมกับ gc.collect() จะเป็นการบังคับคืน Cache Blocks ทั้งหมดกลับสู่ระบบปฏิบัติการอย่างแท้จริงครับ"
                

            


            
            

                

                    ⚠️ Q6: "ในฟังก์ชัน cancel_task เธอจัดการงานอย่างไรถ้างานนั้นกำลังรันอยู่บนการ์ดจอแล้ว?"
                

                

                    คำตอบสั้นและเด็ดขาด: "เราใช้ Dual-Mode Cancellation ครับ ถ้างายังรอในคิว จะทำ Soft Cancel (ปรับ Flag เป็น cancelled แล้วข้าม) แต่ถ้างายกำลังรันบน GPU อยู่จริง จะทำ Hard Cancel โดยส่งสัญญาณ HTTP POST ไปที่ /sdapi/v1/interrupt ของ Forge Engine เพื่อสั่งให้ GPU หยุดรอบการ Denoising ทันที พร้อมกับยกเลิก asyncio Future บน Python Worker ทำให้ GPU คืนรอบการทำงานได้อย่างสมบูรณ์ครับ"

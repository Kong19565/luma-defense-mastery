สิ่งที่เกิดขึ้นเมื่อแปลงรอยวาดส่งไปให้โมเดล Latent Diffusion

1. สูตรการชดเชยมาตราส่วน (Affine Coordinate Transform): X_nat = ((X_client - rect.left) / rect.width) * W_nat
Y_nat = ((Y_client - rect.top) / rect.height) * H_nat
ช่วยให้แม้ผู้ใช้จะซูมเบราว์เซอร์ ย่อหน้าต่าง หรือเปิดบนมือถือ พิกัดของหัวแปรงจะถูก Normalize กลับไปยังตำแหน่งพิกเซลจริงของภาพได้แม่นยำ 100%
2. Dynamic Brush Scaling บนหน้าจอ: realBrushSize = brushSize * (canvas.width / rect.width)
ชดเชยขนาดหัวพู่กันตามอัตราส่วนการย่อของ CSS เพื่อให้ความหนาของเส้นที่วาดบนภาพความละเอียดสูง มีขนาดสอดคล้องกับขนาดหัวแปรงที่ผู้ใช้มองเห็นบนหน้าจอ
3. Compositing Pipeline (ขาวบนดำสนิท): ใช้เทคนิค destination-in ร่วมกับ destination-over บน Offscreen Canvas เพื่อส่งออกภาพ Binary Mask ขาว-ดำ (#FFFFFF บน #000000) สำหรับส่งให้ AI นำไปคูณกับ Noise ใน Latent Space
4. Downsampling 256px Speedup ใน measure(): แทนที่จะอ่านภาพ 4096×4096 (16 ล้านพิกเซล) ฟังก์ชัน measure() จะย่อลง Canvas จำลอง 256px ก่อนนับพื้นที่ระบาย ช่วยให้ประเมิน Coverage (0–1) ได้ในเสี้ยววินาที ไม่กระตุก

🧠 คลังคำตอบสำเร็จรูป: สรุป 7 จุดตายที่อาจารย์ชอบจี้ถามฝั่ง Frontend

จำแนวทางคำตอบ 7 ข้อนี้ไว้ให้ขึ้นใจ ตอบได้อย่างมั่นใจ รับเกรด A ได้แน่นอนครับ

1. ทำไมถึงเลือกแปลง Mask บนเบราว์เซอร์ด้วย Canvas 2D แทนที่จะส่ง Vector ไปให้ Backend ทำ?

ตอบ: เพื่อลดความซับซ้อนและการประมวลผลบนเซิร์ฟเวอร์ เบราว์เซอร์มี GPU Acceleration ผ่าน HTML5 Canvas 2D ที่ทำงานได้แบบเรียลไทม์ 60 FPS อยู่แล้ว การ Render และ Export ออกมาเป็น Binary PNG ขาว-ดำ (#FFFFFF บน #000000) ที่มีขนาดตรงกับ Natural Resolution ตั้งแต่ต้นทาง ทำให้ Backend และ AI Server รับไปป้อนเข้า VAE Inpaint UNet ได้ทันทีโดยไม่ต้องเสียเวลาคำนวณ Path Rasterization ซ้ำบนการ์ดจอ RTX 3070 ครับ

2. การใช้ Adaptive Polling (2s -> 5s) ดีกว่า WebSocket อย่างไรในโปรเจกต์นี้?

ตอบ: เนื่องจากงานสร้างภาพด้วย Diffusion เป็นงานแบบ Asynchronous Batch Job ที่ใช้เวลารันเป็นช่วงๆ (10-30 วินาที) ไม่ใช่การแชท Real-time การเปิด Persistent WebSocket Connection ค้างไว้จะกิน Socket File Descriptors บนเซิร์ฟเวอร์โดยไม่จำเป็น ขณะที่ Adaptive Polling ทำงานแบบ Stateless หากผู้ใช้ปิดหน้าเว็บหรือเน็ตหลุดจะไม่เกิด Connection Leak บน Nginx Gateway และยังทำงานร่วมกับ HTTP Caching ได้อย่างสมบูรณ์ครับ

3. ทำไมทีมถึงเปลี่ยนจาก React 18/Zustand มาเป็น Zero-Build Vanilla HTML/CSS/JS?

ตอบ: เพื่อขจัดความซับซ้อนของ Build Pipeline (ไม่มี Node.js, Vite, หรือ npm dependency ให้พัง), สามารถเปิดรันได้ทันทีผ่านคำสั่งสั้นๆ เช่น python3 -m http.server 5500, ลด Memory Footprint และขจัดปัญหา Re-render Overhead ของ Virtual DOM ขณะลากวาดพู่กันความถี่สูง (60-120 Hz) ทำให้ Canvas วาดเส้นได้ลื่นไหลระดับ Native และง่ายต่อการ Debug และทดสอบด้วย Unit Test แบบ pure ES modules ครับ

4. กลไก watchToken ป้องกัน Stale Response และ Race Condition อย่างไรเมื่อผู้ใช้กด Cancel หรือสลับงาน?

ตอบ: เมื่อผู้ใช้สั่งหยุด สลับดูงานอื่น หรือกดสร้างใหม่ ฟังก์ชัน stopWatching() จะเพิ่มค่า watchToken += 1 ทันที เมื่อการร้องขอ Polling รอบก่อนหน้าตอบกลับมา ระบบจะตรวจสอบ token !== watchToken หากค่าไม่ตรงกัน จะทำการทิ้ง (Discard) คำตอบนั้นทันที ทำให้ไม่มี Response จากงานเก่ามาเขียนทับหรือเปลี่ยนสถานะของ UI ปัจจุบันครับ

5. ทำไมถึงต้องบังคับขนาดภาพพรีเซ็ตให้หารด้วย 8 ลงตัว (เช่น 512, 680, 768) ด้วย snapSize()?

ตอบ: เพราะโมเดล Stable Diffusion ทำงานบน Latent Space ผ่านโครงข่าย VAE ซึ่งมี Downsampling Factor เท่ากับ 8 เท่า (f=8) หากหน้าบ้านยอมให้ส่งขนาดที่ไม่หารด้วย 8 ลงตัว เช่น 685 มิติใน Latent Space จะกลายเป็น 85.625 ซึ่งเป็นทศนิยม ทำให้เกิด Tensor Shape Mismatch ใน UNet Attention Layers ทันที การกรองด้วย snapSize() ตั้งแต่ฝั่ง Frontend จึงเป็นหัวใจของ Pre-flight Data Sanitization ครับ

6. ทำไมถึงเก็บ Token ใน LocalStorage แล้วแนบ Bearer Header แทนการใช้ Cookie ปกติ?

ตอบ: เนื่องจากสถาปัตยกรรมระบบเป็นแบบ Decoupled API (Frontend อยู่พอร์ต 5500, Backend อยู่พอร์ต 8000) ซึ่งรันคนละ Origin กัน การใช้ Authorization Header แบบ Bearer <token> ช่วยป้องกันการโจมตีประเภท CSRF (Cross-Site Request Forgery) และแก้ปัญหาเรื่อง Third-party Cookie Blocking บนเบราว์เซอร์สมัยใหม่ได้อย่างเด็ดขาด

7. ทำไมฝ่าย Frontend ถึงต้องมีโมดูล families.js สำหรับตรวจจับตระกูลโมเดล และกรอง LoRA Dropdown แบบ Real-time?

ตอบ: เพื่อปฏิบัติตามหลักการ User Experience (UX) และการตรวจสอบข้อมูลล่วงหน้า (Pre-flight Validation) โดยสถาปัตยกรรม SD 1.5, Illustrious XL, และ Pony XL ใช้โครงข่าย Text Encoder และมิติ Latent ที่ไม่เท่ากัน หากผู้ใช้จับคู่ LoRA ผิดตระกูล ภาพที่ได้จะพังเสียหาย โมดูล families.js จะอ่านค่า family แล้วกรอง Dropdown ให้แสดงเฉพาะ LoRA ที่เข้ากันได้กับ Base Model ทันที พร้อมติดป้ายกำกับสี ช่วยป้องกันความผิดพลาดตั้งแต่ฝั่งผู้ใช้ก่อนส่งคำขอไปยังเซิร์ฟเวอร์ครับ
